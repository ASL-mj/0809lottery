# 星额台品牌、自动任务与性能优化设计

## 1. 目标与范围

本轮将 0809 多账号工作台品牌调整为“星额台”，在不改变现有工作台信息密度和操作方式的前提下，将“自动抽奖计划”升级为“自动任务”。自动任务包含两类任务：自动抽奖和自动领取每日签到抽奖次数。每个账号的任务独立配置、独立执行、独立记录。

本轮同时优化首屏请求链路，定位并减少重复请求；修复会话撤销错误分类，使 502 网关错误不再被误报为认证失效。代码只在本地验证，用户验收前不推送或部署线上。

不包含：新的远端平台接口猜测、批量账号操作、跨账号统计、生产环境配置变更、秘密凭据迁移或展示。

## 2. 已确认的交互设计

### 2.1 品牌

- 网站名称统一为“星额台”。
- 使用内嵌 SVG Logo，采用现有黑白灰配色，图形为双环与连接节点，表达多账号和额度管理。
- 页面标题、登录页、工作台头部、README 和 Makefile 帮助文本统一使用新名称。

### 2.2 自动任务面板

- 沿用现有“自动抽奖计划”面板的结构、间距和计划行，不新增任务卡片组件。
- 面板标题改为“自动任务”，右上角按钮改为“设置自动任务”。
- 每条计划行显示：执行时间或时间段、任务类型、频率、执行状态、Switch、移除按钮。
- Switch 独立控制该计划启用状态；启用/停用不改变时间和任务类型。
- 设置弹窗负责新增和编辑任务，字段包括任务类型、启用状态、执行方式、开始时间、结束时间（随机时段必填）。
- 执行方式保留“固定时间”和“时间段内随机”。固定时间每天执行一次；随机时段每天在指定窗口内执行一次。
- 每日领取抽奖次数任务每天最多执行一次；已有每日领取动作记录继续作为幂等依据。

## 3. 数据模型与兼容

### 3.1 任务计划

保留现有计划的稳定 ID 和每日执行记录，在 `AutoDrawSchedule` 语义上增加字段：

```text
id          string
task_type   draw | claim
enabled     bool
kind        fixed | random
start       HH:MM
end         HH:MM (random 必填)
```

旧 `draw_schedules` 数据读取时映射为 `task_type=draw, enabled=true`。兼容读取期间仍接受旧字段；新页面通过 `auto-tasks` 路由保存新结构。保留 `draw-schedule` 路由作为兼容别名，避免旧客户端立即失效。

每日计划实例继续使用账号、计划 ID 和日期组成的稳定键，并保存幂等键、执行状态、结果、奖励和错误信息。`draw` 复用现有 `DrawAvailableScheduled`；`claim` 复用现有 `ClaimDaily`，均在账号级锁下执行。

### 3.2 API

- `GET /api/bootstrap`：一次返回账号脱敏元数据、本地快照、任务计划和有限数量的最新本地运行日志。不得触发远端平台请求。
- `GET|PUT /api/accounts/{id}/auto-tasks`：读取或整体替换该账号任务计划。
- `POST /api/accounts/{id}/auto-tasks/{task_id}/toggle`：切换单条任务启用状态，返回规范化计划。
- 现有 `GET|PUT /api/accounts/{id}/draw-schedule` 保留并转换到新模型。
- 现有业务查询接口继续保留，前端按需调用。

Bootstrap 响应只包含脱敏的账号字段、快照和任务状态，不包含密码、Cookie、Bearer Token、远端会话 ID、幂等键或未清理的上游正文。

## 4. 性能设计

### 4.1 当前瓶颈

当前页面加载顺序包含 `/api/accounts`、`/api/auto-draw-status`、`/api/runtime-logs`，随后为每个账号请求一次中奖记录。`/api/accounts` 内部还会逐账号串行调用签到状态，单次超时为 35 秒。重复进入页面会再次执行这组请求。

### 4.2 首屏与按需加载

1. 页面启动只请求 `/api/bootstrap`，先用本地快照绘制当前账号。
2. 不在首屏自动查询远端签到状态、中奖记录、活动和 Token 用量。
3. 当前账号可见区域按需刷新；切换账号后并行刷新该账号的业务区域。
4. 采用 30 秒 TTL 和按账号/接口维度的 in-flight Promise 去重。页面从后台恢复时只刷新过期数据。
5. 后端 bootstrap 只读本地状态，不执行网络调用；远端查询在独立接口中按需执行。

### 4.3 观测

服务端记录以下结构化字段：阶段名、账号脱敏 ID、耗时、上游 HTTP 状态、错误类别、请求是否命中缓存。禁止记录请求头、Cookie、Token、密码、幂等键和响应正文。

本地验收采集三组数据：首次打开、浏览器刷新、切换账号。每组记录请求数量、首屏可见时间、当前账号远端数据完成时间和服务端阶段耗时。

## 5. 会话撤销错误处理

客户端保留上游状态码和安全错误类型。服务端 `revokeSessions` 不再将所有错误固定包装为“认证可能已失效”。映射规则如下：

| 错误 | HTTP | 用户提示 |
| --- | ---: | --- |
| 上游 401/403 | 401 | 认证已失效，请重新认证 |
| 上游 502/503/504 | 502 | 平台网关暂时不可用，请稍后重试 |
| 请求超时 | 504 | 平台请求超时，请稍后重试 |
| 其他上游 4xx/5xx | 502 | 平台拒绝了会话撤销 |
| 响应解析或协议错误 | 502 | 平台会话接口响应异常 |

日志记录阶段 `upstream_sessions` 或 `upstream_revoke`、状态码和错误类别。撤销其他会话成功后，优先使用上游返回的撤销数量；重新拉取会话列表失败时返回“结果待确认”，不删除未确认的本地秘密或会话账本。

## 6. 测试设计

- 状态层：旧计划兼容映射、新任务类型、启用状态、固定/随机时间校验、每日领取唯一执行、重启恢复。
- 调度层：`draw` 与 `claim` 分发、账号锁、幂等键、失败重试和运行日志。
- Web 层：bootstrap 只读本地状态、auto-tasks CRUD/toggle、旧 draw-schedule 路由兼容、敏感字段扫描。
- 性能层：重复请求去重、TTL 命中和过期刷新；确认 bootstrap 不调用远端客户端。
- 会话层：上游 401、403、502、503、504、超时、协议错误分别映射到正确 HTTP 状态和用户提示；成功撤销后计数和账本更新保持一致。
- 静态层：Go 格式化、`go test ./...`、`go vet ./...`、`make build`、内嵌前端脚本语法检查、`git diff --check`。

## 7. 本地验收停止条件

实现完成并通过测试后，使用当前项目内的环境文件启动本地服务，提供本地 URL。用户验收前不执行 `git push`、生产部署、远端会话清理或环境配置变更。若用户发现 UI、请求瀑布或会话错误提示问题，先在本地修复并重新验证。
