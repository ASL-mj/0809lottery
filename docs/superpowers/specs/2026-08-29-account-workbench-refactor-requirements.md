# 0809 多账号工作台重构需求文档

**版本：** 1.0  
**日期：** 2026-08-29  
**状态：** 待评审  
**范围：** 本地 0809 多账号工作台

## 1. 背景

现有工作台已经能够分别查询订阅、签到、领取每日抽奖次数、抽奖、查询活动信息、购买抽奖次数/通行证，并在三个时间窗口内自动抽奖。但账号来源固定为五组环境变量，认证状态、Cookie 与令牌保存在同一 JSON 状态文件中；当已保存认证失效时，服务端会自动使用密码重新登录。

平台存在会话数量限制。每次密码登录可能新建一个平台会话，累计达到约 50 个会话后账号无法再登录。重构的核心目标是在保留当前业务能力的前提下，将账号改为用户可管理的列表，并把认证改造成可审计、可复用、不会在后台反复创建会话的生命周期管理能力。

## 2. 目标与边界

### 2.1 目标

1. 用户可在工作台中新增、编辑、停用、重新认证和删除任意数量的账号，不再受 `ACCOUNT_A` 到 `ACCOUNT_E` 的固定配置限制。
2. 业务读取和后台任务优先复用有效令牌、Cookie 与刷新会话；不得因重试、页面刷新或定时任务而静默密码登录。
3. 对本工作台创建且可被远端唯一识别的会话，保留少量持久会话并在平台支持时清理旧的一次性会话；绝不误删用户在浏览器、手机或其他设备创建的未知会话。
4. 每项额度均按经验证的规则换算为美元，并保留原始值、计算公式、汇率/单位快照和查询时间，避免把未确认的数值伪装成 `$`。
5. 保留当前所有单账号业务能力、幂等保护、自动抽奖计划和运行日志。

### 2.2 不在范围内

- 跨账号总览、合并统计、批量刷新、批量购买或批量抽奖。
- 代替用户修改平台密码、绕过验证码、双因素认证或平台风控。
- 清理无法证明由工作台创建的远端会话。
- 猜测或调用尚未确认的登出、会话列表、会话撤销接口。
- 在浏览器、普通日志、快照或接口响应中暴露密码、Cookie、访问令牌、刷新令牌、远端会话 ID 或幂等键。

## 3. 用户与使用原则

| 角色 | 能力 | 约束 |
| --- | --- | --- |
| 工作台用户 | 管理自己的账号、执行单账号操作、查看认证与会话清理状态 | 仅能操作本地工作台保存的账号 |
| 工作台服务 | 向 0809 发起认证和业务请求，保存脱敏的业务状态 | 不向浏览器返回认证材料 |
| 0809 平台 | 决定认证、会话数量、额度和抽奖结果 | 是所有余额、额度、活动与会话状态的权威来源 |

工作台继续采用“一张账号卡片对应一个独立账号”的交互。卡片之间不得共享认证、动作结果、额度或定时抽奖状态；一个账号异常不能遮蔽其他账号结果。

## 4. 已有能力的保留范围

| 能力 | 重构后要求 |
| --- | --- |
| 订阅查询 | 单账号查询订阅、剩余额度、到期时间；保留最近成功快照与查询时间。 |
| 签到 | 每日幂等；显示成功、失败、已签到及当日实际签到额度。 |
| 每日赠送抽奖次数 | 单账号领取、结果核对、显示新增与当前可抽次数；领取不自动抽奖。 |
| 抽奖次数查询 | 显示当前可抽、锁定和今日已用次数。 |
| 手动抽奖 | 单次、单账号操作；显示跳过、成功或失败、奖品和额度变化。 |
| 活动信息 | 显示今日消耗、消费激励进度、幸运积分、下一档差额和当天价格。 |
| 购买 | 保留购买一次抽奖与购买当日通行证；价格必须来自实时活动信息，且维持幂等与结果核对。 |
| 自动抽奖 | 每账号每天在北京时间 `08:00-09:00`、`13:00-14:00`、`18:00-19:00` 各随机执行一次；重启后不重复执行。 |
| 运行日志 | 保留自动抽奖成功、跳过、失败的脱敏日志，以及七天保留策略。 |

## 5. 功能需求

### FR-1：账号注册表与自助管理

1. 工作台必须支持新增任意数量的账号。新增时收集显示名称、登录名和密码；登录名和密码只进入秘密存储，不进入普通账号注册表。
2. 账号卡片必须显示显示名称、脱敏登录名、启用状态、认证健康状态和最近业务快照。长名称必须换行，不能挤出操作按钮。
3. 用户必须能够修改显示名称、更新登录凭据、启用或停用账号。停用后该账号不得发起自动抽奖或任何后台认证请求。
4. 用户必须能够删除账号。删除操作需要明确确认，先停止该账号的后续计划，再删除本地秘密与账号级业务状态；已知远端工作台会话只能在平台接口确认后作为可选清理项处理。
5. 同一远端用户 ID 不得默认绑定到两个本地账号。首次成功认证后，如发现重复绑定，工作台必须阻止启用并要求用户显式迁移或删除旧绑定。
6. 为兼容现有部署，初始迁移应把已有环境变量账号导入注册表，保留原 `account-a` 至 `account-e` 的本地 ID、标签和已有业务记录。

### FR-2：认证复用与显式重新认证

1. 所有读取、签到、领取、购买、手动抽奖和自动抽奖必须通过统一认证入口取得会话，不能各自调用登录接口。
2. 认证优先级必须为：有效的已保存业务令牌 -> 已保存父令牌的无副作用验证 -> 刷新 Cookie 换取新令牌 -> **需要用户显式重新认证**。
3. 只有用户在卡片上主动执行“重新认证”并确认后，工作台才可以使用密码调用登录接口。页面打开、普通查询、失败重试、自动抽奖、服务重启和网络恢复不得自动密码登录。
4. 每个账号的认证恢复必须串行化；并发请求等待并复用第一个请求持久化的结果，不能形成登录风暴。
5. 一次业务请求最多进行一次认证恢复和一次原业务重试。网络错误、5xx、超时、429 或未知错误不得降级为密码登录。
6. 刷新或验证失败时，卡片显示“需要重新认证”及脱敏原因。后台任务记录安全错误并跳过本次操作，不弹出密码输入、不创建新会话。

### FR-3：会话数量保护与清理

1. 工作台必须将平台会话上限配置化。首版默认使用用户报告的上限 `50`、安全余量 `5`，并将本工作台每账号保留的持久会话数默认设为 `2`（可配置为 1 到 3）。
2. 工作台必须区分“已确认由本工作台创建并可远端识别”的会话与未知会话。只有前者可以被列入清理候选。
3. 若平台具备已验证的会话列表和撤销/登出能力，工作台必须先提供清理预览：保留哪些会话、计划删除哪些会话、删除理由和预计释放数。首次执行及策略变更必须由用户确认。
4. 清理必须保留当前活跃会话和选定的备用持久会话；旧的、已被工作台记录且不再需要的会话按最旧优先清理。
5. 在需要密码登录前，如可读取远端会话清单，工作台必须先做容量预检；当总数达到上限减安全余量时，先清理已确认的工作台旧会话。若无法安全释放容量，拒绝创建新会话并给出操作指引。
6. 如果尚未确认平台会话管理接口，工作台必须明确显示“远端会话清理不可用”。此时不会伪造清理结果，也不会让后台自动登录；用户仍可在明确确认风险后进行一次人工重新认证。
7. 不得因为刷新接口、桥接接口或响应设置了 Cookie 就假定不会增加远端会话。它们是否创建会话必须通过平台接口契约和实测确定，并进入会话账本。

### FR-4：秘密与审计边界

1. 密码、Cookie、父访问令牌、活动令牌、远端会话标识和登录名原文必须保存到可插拔的本地秘密库；普通状态文件只保存账号元数据、脱敏认证状态、动作记录、业务快照和日志。
2. 首版运行环境应优先使用操作系统钥匙串或部署环境的秘密库。秘密库不可用时允许账号处于“需手动重新认证”状态，但不得退回到普通 JSON、环境变量或浏览器本地存储明文保存密码。
3. API 响应、前端状态、运行日志、错误文本、测试夹具和持久化快照必须采用允许字段白名单，不能依赖字符串替换来保证不泄露认证材料。
4. 所有变更账号、重新认证、会话清理、购买和抽奖的接口必须继续受本地工作台访问控制保护，并增加同源请求校验与 CSRF 防护。

### FR-5：实际额度计算

1. 每个额度结果必须保留：原始数值、原始字段语义、美元数值、计算公式版本、`quota_per_unit`、显示类型、可能使用的汇率、来源接口和查询时间。
2. 所有计算必须使用定点十进制或等价精确表示，页面仅在最后展示时四舍五入到两位小数；不得用浮点累计产生金额误差。
3. 订阅额度必须分别计算总额、已用和剩余：`remaining_raw = max(total_raw - used_raw, 0)`。无限订阅按无限展示，不能伪造余额。
4. 已经由上游明确以美元返回的字段不得再次除以单位或乘除汇率。原生额度只有在其单位语义经验证后才可以换算为美元。
5. `quota_display_type`、`usd_exchange_rate` 和自定义货币字段不能仅凭字段名参与公式；必须以平台页面/API 的对应关系验证后，登记为版本化换算规则。
6. 当某个字段无法确认换算规则或状态配置缺失时，页面显示“额度换算待确认”及查询时间，不显示误导性的 `$0.00` 或猜测的美元数值。
7. 不同来源的值不得未经证明相加。例如订阅剩余、用户用量、签到奖励、抽奖奖励和活动消费必须各自标注来源；只有平台契约确认同一口径后才允许汇总。

### FR-6：现有动作与调度的认证约束

1. 既有签到、领取、抽奖、购买和查询继续使用各自的幂等、互斥和结果核对机制。
2. 自动抽奖只能使用已可用或可刷新成功的持久会话；认证不可恢复时，计划标记为跳过/失败并写入脱敏日志，不能触发密码登录。
3. 新增或重新启用账号不会自动发起订阅查询、活动查询或登录。用户第一次操作或主动重新认证后才建立业务快照。
4. 账号列表加载只读取本地快照和认证状态，不能对所有账号发起上游请求。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 隔离性 | 账号、锁、动作键、快照和调度计划均以账号 ID 隔离。 |
| 并发 | 单账号认证和有副作用动作互斥；不同账号可以并行。 |
| 可恢复性 | 服务重启后保留账号元数据、认证健康状态、动作幂等记录、计划和日志；不会重复执行自动抽奖。 |
| 可观测性 | 记录认证路径类别、会话清理摘要、换算规则版本、失败码和时间，不记录秘密值。 |
| 性能 | 账号列表从本地状态加载；单账号操作按现有超时控制执行。 |
| 兼容性 | 现有账号 ID、业务动作路径和历史业务记录在迁移后可继续使用。 |

## 7. 外部前置条件与失败行为

当前代码已确认登录、令牌验证、刷新和抽奖桥接接口；尚未确认平台的会话列表、会话撤销或登出接口。因此会话清理功能的交付依赖以下可验证条件：

1. 确认会话查询接口、认证方式、响应中的稳定会话 ID 和分页规则。
2. 确认会话撤销或登出接口、幂等行为、是否会撤销当前会话以及错误码。
3. 确认密码登录、刷新和桥接是否分别创建、复用或替换远端会话。
4. 以脱敏的真实响应与平台页面核对额度字段的美元语义和公式。

在任一条件未满足前，工作台不得执行对应的远端清理或展示“已清理”结论；额度字段保持待确认状态，认证仅使用可证明安全的复用、验证和刷新路径。

## 8. 验收标准

1. 用户可在工作台中新增、编辑、停用、重新认证和删除账号，且不需要编辑五组环境变量。
2. 列表和任意后台任务在无显式重新认证操作时，对登录接口的调用次数为零；并发读取同一失效账号不会产生多个刷新或登录请求。
3. 刷新成功后，后续动作复用新认证状态；刷新返回认证拒绝后，状态为“需要重新认证”，而不是自动密码登录。
4. 在模拟 50 个会话上限的测试中，容量预检、保留 2 个持久会话、安全余量和仅清理已知工作台会话的规则均成立；未知会话永不成为删除目标。
5. 若会话接口未接入，界面和日志明确显示不可用，不产生虚假的删除记录。
6. 订阅总额、已用、剩余、签到奖励、抽奖奖励、活动价格和消费进度均能输出带来源和规则版本的美元金额；已是美元的值不会重复换算，未知规则不展示伪美元值。
7. 签到、领取、抽奖、购买、活动查询、自动抽奖和运行日志的现有回归测试保持通过，并新增账号管理、认证路径、会话清理和额度换算覆盖。
8. 对接口响应、日志、普通状态文件和前端构建产物进行秘密扫描，确认其中不含测试密码、Cookie、Bearer 令牌、刷新令牌或远端会话标识。
