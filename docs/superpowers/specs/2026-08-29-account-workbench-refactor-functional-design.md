# 0809 多账号工作台重构功能详细设计

**版本：** 1.0  
**日期：** 2026-08-29  
**对应文档：** `2026-08-29-account-workbench-refactor-requirements.md`、`2026-08-29-account-workbench-refactor-design.md`  
**状态：** 待实施

## 1. 功能原则

工作台从固定五个环境变量账号改为用户可管理的账号注册表。每张账号卡片仍独立执行订阅、签到、领取、抽奖、购买、活动查询和自动抽奖；不会增加跨账号统计、批量操作或共享认证。

1. 新增账号、页面刷新和后台任务都不会自动密码登录。
2. 页面只显示脱敏登录名、认证状态、额度来源和安全错误，不显示密码、Cookie、令牌或远端会话 ID。
3. 会话清理只有在平台接口被验证后才能执行；未验证时必须明确显示不可用。
4. `$` 只表示已确认的美元金额；单位规则未确认时显示“额度换算待确认”。
5. 停用账号后不得发起后台认证或自动抽奖；删除账号需要确认并清除该账号的本地数据。

## 2. 状态模型

### 2.1 账号生命周期

| 状态 | 含义 | 允许动作 |
| --- | --- | --- |
| `enabled` | 可执行用户操作与自动抽奖 | 所有现有操作、验证、重新认证、编辑、停用、删除 |
| `disabled` | 用户主动暂停 | 编辑、验证、重新启用、删除；无后台请求 |
| `deleting` | 删除确认已提交 | 不接受新操作；完成后移除，失败则回到 `disabled` |

首次成功验证或重新认证后绑定远端用户 ID。同一远端用户 ID 已被其他本地账号绑定时，新账号必须停用并提示用户迁移或删除旧绑定，不能复制或覆盖既有秘密。

### 2.2 认证健康状态

| 状态 | 卡片文案 | 行为 |
| --- | --- | --- |
| `uninitialized` | 未建立会话 | 普通业务动作返回重新认证需求 |
| `usable` | 会话可用 | 复用已保存令牌和 Cookie |
| `refreshable` | 会话待验证或临近过期 | 允许无密码验证和刷新 |
| `requires_reauth` | 需要重新认证 | 不自动登录 |
| `session_capacity_protected` | 已保护平台会话上限 | 阻止新登录，展示原因 |
| `unavailable` | 认证服务暂不可用 | 保留快照，允许稍后重试 |

### 2.3 会话管理能力

| 能力 | 含义 | 页面动作 |
| --- | --- | --- |
| `unsupported` | 未确认会话列表/撤销 API | 仅显示不可用说明 |
| `readable` | 可安全读取远端清单 | 允许只读预览 |
| `revocable` | 已验证读取与撤销语义 | 允许预览并确认清理 |

2026-08-29 的公开页面/脚本检查仅发现认证刷新和抽奖桥接线索，未发现可确认的会话列表、撤销或登出契约。这不是平台不存在该接口的结论，而是首版必须按 `unsupported` 交付的安全边界。

### 2.4 金额状态

| 状态 | 表现 | 可用于余额/购买判断 |
| --- | --- | --- |
| `confirmed` | 显示美元、来源、公式和时间 | 可以 |
| `unverified` | 显示“额度换算待确认” | 不可以 |
| `unavailable` | 显示“暂不可计算” | 不可以 |

## 3. 页面设计

### 3.1 页面框架

顶部只提供 `新增账号` 和 `系统运行日志`。不得展示跨账号余额、消费、抽奖次数、成功率或总计数。账号列表加载只读取本地注册表、认证健康状态和最近快照，不对全部账号发起上游请求。

### 3.2 账号卡片

每张卡片按以下分组展示：

1. 身份栏：显示名称、脱敏登录名、启停状态、认证状态、最近查询时间和账号菜单。
2. 认证与会话栏：`验证会话`、`重新认证`、会话能力/清理预览入口；不显示秘密。
3. 额度栏：订阅总额、已用、剩余、用户用量、签到/抽奖奖励；每项附来源、规则状态和查询时间。
4. 原有业务栏：订阅刷新、签到、领取、抽奖次数查询、手动抽奖、活动刷新、购买一抽、购买通行证。
5. 自动抽奖栏：早/午/晚三个窗口的待执行、运行、完成、跳过或失败状态。
6. 局部反馈栏：只显示当前账号最近一次动作结果并接受键盘焦点。

长名称和反馈允许断行。按钮有稳定最小宽度；在 `390px` 宽度下页面不得横向滚动。

### 3.3 新增与编辑账号

`新增账号` 使用原生 `dialog`，字段如下：

| 字段 | 验证 | 保存位置 |
| --- | --- | --- |
| 显示名称 | 去空白后 1-80 字符 | 非秘密注册表 |
| 登录名 | 去空白后 1-256 字符 | SecretVault；页面仅脱敏显示 |
| 密码 | 1-512 字符 | SecretVault 或本次请求内存 |
| 保存密码 | 默认启用 | 控制密码是否持久保存 |
| 自动抽奖 | 默认启用 | 非秘密注册表 |

新增成功只创建本地卡片，认证状态为 `uninitialized`，页面提示“请重新认证建立持久会话”。它不得调用登录、刷新、订阅或活动接口。编辑凭据同样不触发登录。

`停用账号` 立即阻止自动调度器产生新计划；未执行计划在下一次 Tick 标记为跳过。`删除账号` 先说明将清除的本地秘密、动作、快照、计划和日志，用户输入确认词 `DELETE` 后执行。远端会话不随删除默认撤销。

## 4. 用户流程

### 4.1 验证会话

`验证会话` 从不读取或提交密码，按以下顺序执行：

1. 读取 SecretVault 的认证材料；不存在时返回 `requires_reauth`。
2. 令牌尚未临近过期时复用；否则调用 `/api/user/self` 验证。
3. 只有明确认证拒绝时调用 `/api/user/auth/refresh` 一次。
4. 刷新成功后保存新的认证材料并返回 `usable`。
5. 刷新认证拒绝返回 `requires_reauth`；网络错误、5xx、429、超时和解析错误返回 `unavailable`。

任何一种失败都不能降级为密码登录。

### 4.2 重新认证

`重新认证` 是唯一允许密码登录的路径：

1. 对话框展示“本操作可能创建一个新的平台会话”和当前会话能力。
2. 当能力为 `readable` 或 `revocable` 时，服务端先读取远端清单；数量达到 `session_limit - safety_margin` 时，返回安全清理预览或容量保护错误。
3. 用户确认后只调用一次密码登录，保存成功会话并绑定远端用户 ID。
4. 登录失败、容量保护或远端用户重复绑定时均不再次登录。

页面打开、普通查询、失败重试、服务重启、自动抽奖、签到、领取、购买和手动抽奖都不能触发此流程。

### 4.3 会话清理

当能力为 `revocable` 时，预览只返回：保留数、候选数、安全别名、策略摘要和 60 秒有效的 `preview_id`。不会返回远端会话 ID、IP、Cookie、设备原始名称或 Token。

服务端仅能选择同时满足以下条件的会话：已登记为工作台创建、远端仍匹配、不是当前/固定保留会话、超过持久会话上限。确认清理时必须重新读取远端清单；预览过期或清单变化则中止。未知会话永远不进入候选。

`unsupported` 时页面显示“平台会话管理未接入”，不能显示伪清理按钮或“已清理”日志。

### 4.4 原有业务与自动抽奖

| 动作 | 认证意图 | 成功后刷新 | 认证不可恢复时 |
| --- | --- | --- | --- |
| 刷新订阅 | `read_only` | 订阅和额度快照 | 提示重新认证 |
| 签到 | `side_effect` | 签到记录和奖励 | 不提交签到 |
| 领取 | `side_effect` | 领取和抽奖次数 | 不提交领取 |
| 查询次数 | `read_only` | 抽奖次数快照 | 提示重新认证 |
| 手动抽奖 | `side_effect` | 奖励和次数快照 | 不提交抽奖 |
| 刷新活动 | `read_only` | 消费、积分、价格 | 提示重新认证 |
| 购买 | `side_effect` | 保留原幂等与对账 | 不重复提交 |

自动抽奖维持北京时间 `08:00-09:00`、`13:00-14:00`、`18:00-19:00` 每账号随机一次。它只使用 `scheduled_automation` 认证意图；认证需要重新登录时，计划记为 `skipped`，文案为“需要重新认证，未创建新平台会话”。

## 5. 本地 API 契约

所有接口沿用 HTTP Basic Auth。写操作需要同源 `Origin`/`Referer` 检查与 `X-CSRF-Token`。统一错误体：

```json
{"code":"AUTH_REAUTH_REQUIRED","message":"该账号需要重新认证","request_id":"safe-local-id"}
```

`request_id` 仅用于本地审计，不是上游幂等键。

| 方法 | 路径 | 请求 | 成功结果 |
| --- | --- | --- | --- |
| `POST` | `/api/accounts` | `label`、`username`、`password`、`save_password`、`auto_draw_enabled` | 脱敏账号，状态 `uninitialized` |
| `PATCH` | `/api/accounts/{id}` | `label`、`enabled`、`auto_draw_enabled` | 更新后的脱敏账号 |
| `PUT` | `/api/accounts/{id}/credentials` | `username`、`password`、`save_password` | 更新后的脱敏账号，不登录 |
| `POST` | `/api/accounts/{id}/auth/validate` | 空 | 认证状态 |
| `POST` | `/api/accounts/{id}/auth/re-authenticate` | 可选临时密码、`save_password`、`confirm` | 认证状态，不含秘密 |
| `GET` | `/api/accounts/{id}/sessions/cleanup-preview` | 空 | 能力或安全预览 |
| `POST` | `/api/accounts/{id}/sessions/cleanup` | `preview_id`、`confirm:true` | 脱敏清理结果 |
| `DELETE` | `/api/accounts/{id}` | `confirmation:"DELETE"` | `204 No Content` |

既有签到、领取、抽奖、活动、购买、次数、自动抽奖和运行日志路径保持兼容，并统一经过 SessionBroker。

## 6. 金额契约

所有美元金额使用结构化对象，避免 JSON 浮点误差：

```json
{
  "currency":"USD",
  "value":"12.345678",
  "display":"$12.35",
  "state":"confirmed",
  "source":"subscription.amount_total",
  "formula":"quota-per-unit-v1",
  "observed_at":"2026-08-29T00:00:00Z"
}
```

内部计算使用精确有理数。`quota_per_unit`、`quota_display_type`、`usd_exchange_rate` 和自定义货币字段同次保存为规则快照；只有已验证规则允许将原生额度转换为美元。订阅总额、已用、剩余按 `max(total_raw - used_raw, 0)` 分别计算；用户用量、活动消耗和奖励不经证明不得相加。

## 7. 错误矩阵

| 错误码 | 文案 | 自动行为 |
| --- | --- | --- |
| `ACCOUNT_DISABLED` | 账号已停用 | 不发起上游请求 |
| `AUTH_REAUTH_REQUIRED` | 该账号需要重新认证 | 不登录 |
| `AUTH_UNAVAILABLE` | 认证服务暂不可用，请稍后重试 | 不修改令牌 |
| `SESSION_CAPACITY_PROTECTED` | 为保护平台会话上限，未创建新会话 | 不登录 |
| `SESSION_MANAGEMENT_UNAVAILABLE` | 平台会话管理未接入 | 不伪造预览/清理 |
| `QUOTA_CONVERSION_UNVERIFIED` | 额度换算待确认 | 不显示 `$0.00` |
| `ACTION_RESULT_UNKNOWN` | 结果待确认，请刷新对应状态 | 不重复提交 |
| `DUPLICATE_REMOTE_ACCOUNT` | 该平台账号已存在于工作台 | 不覆盖秘密 |

## 8. 验收场景

1. 用户新增第六个账号后出现第六张卡片，网络记录没有登录请求。
2. 令牌失效但刷新可用时只刷新一次，不登录。
3. 刷新被拒绝时，签到和自动抽奖都不调用登录。
4. 会话数量达到安全阈值且无法安全释放时，显式重新认证被阻止。
5. 会话管理未接入时，界面和日志不产生“已清理”结论。
6. 已验证单位的订阅余额精确显示美元；规则未确认的字段不伪装为美元。
7. 签到、领取、抽奖、购买、自动抽奖和运行日志保持单账号隔离与现有幂等语义。
