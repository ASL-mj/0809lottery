# 0809 多账号工作台

这是一个受 HTTP Basic Auth 保护的本地 Web 页面，用于分别管理多个已配置的 0809 账号。每个账号的操作相互独立：一个账号会话失效不会遮蔽其他账号的结果，也不会产生跨账号统计。

## 功能

- 单页展示多个账号，每个账号一张独立管理卡片。
- 显示有效订阅、有限订阅的剩余额度、到期时间和最近查询状态。
- 所有额度统一按平台 `quota_per_unit` 换算为美元（`$`）显示。
- 对单个账号执行“刷新订阅”。
- 对单个账号只读查询新版抽奖页次数，显示当前可抽、已锁定和今日已用次数。
- 对单个账号执行每日签到；当天成功后按钮显示“已签到”。
- 对单个账号领取每日赠送的抽奖次数；领取结果显示新增次数和当前可抽次数。
- 对单个账号执行一次手动抽奖；结果显示跳过、成功或失败，以及奖品和美元额度（如有）。
- 在状态文件中复用已有 Cookie、父访问令牌和活动令牌。
- 初始加载核对每个账号的签到状态，并读取最近保存的订阅和抽奖次数快照；不会自动查询所有账号的订阅明细。

工作台不提供登录、令牌导入或导出、会话切换、解锁、购买抽数、批量操作、任务调度、通知或跨账号统计。签到、每日领取和手动抽奖均只作用于当前账号；不会自动执行抽奖。

## 认证边界

账号认证状态保存在 `STATE_PATH` 所指向的本地状态文件中，文件必须仅允许工作台服务用户读取。浏览器只能取得账号标签、用户名和经过整理的业务结果；密码、Cookie、父令牌、桥接令牌和原始上游响应不会进入页面或 API 响应。

各账号操作优先复用仍可用的已保存认证状态。本地记录的父令牌到期时，工作台会先向服务端验证该令牌；服务端拒绝后再用已保存的刷新 Cookie 调用 `/api/user/auth/refresh`。只有刷新接口明确返回 `401` 或 `403` 时，才会以受保护环境中的对应 `ACCOUNT_*_USERNAME` 与 `ACCOUNT_*_PASSWORD` 密码登录一次。每个账号的认证恢复会串行执行，等待中的请求会复用刚保存的新会话；网络错误、`5xx` 或 `409` 不会触发额外密码登录。浏览器仍不会接收密码、Cookie 或令牌。

## 配置

1. 将 `config.example.env` 复制到部署目录的私有环境文件，并将权限设为 `600`。
2. 为五个账号设置 `ACCOUNT_A_USERNAME` 与 `ACCOUNT_A_PASSWORD` 至 `ACCOUNT_E_USERNAME` 与 `ACCOUNT_E_PASSWORD`；它们仅在服务端用于令牌刷新。可以用 `ACCOUNT_*_LABEL` 自定义显示名。
3. 设置 `STATE_PATH` 指向已有认证状态文件，并设置 `WEB_USERNAME`、`WEB_PASSWORD` 保护工作台。
4. 保持 `WEB_ADDR` 绑定在 `127.0.0.1`，由 HTTPS 反向代理对外提供访问。

## 运行

```bash
./lottery-bot serve
```

默认监听 `127.0.0.1:18090`。部署前可运行：

```bash

```

## Web API

所有接口均要求 HTTP Basic Auth。

- `GET /`：多账号工作台页面。
- `GET /api/health`：服务健康检查。
- `GET /api/accounts`：账号公开信息与本地订阅快照。
- `POST /api/accounts/{account_id}/checkin`：执行指定账号的每日签到。
- `POST /api/accounts/{account_id}/claim`：领取指定账号当日赠送的抽奖次数。
- `POST /api/accounts/{account_id}/draw`：执行指定账号的一次手动抽奖。
- `POST /api/draw-count/query`：只读查询一个明确账号的当前可抽、锁定和今日使用次数。
- `POST /api/subscriptions/query`：查询一个明确账号，例如：

```json
{"account_id": "account-a"}
```

空账号、`all` 和未知账号会被拒绝。

## 验证

测试覆盖认证保护、账号响应的凭据隔离、已移除路由的 404、单账号请求约束、领取不触发抽奖、手动抽奖单次执行、页面无批量或统计入口，以及令牌失效时自动重新登录并持久化新令牌。
